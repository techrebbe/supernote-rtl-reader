## Existing Close -> handoff -> reopen behavior (main 69e2aa2)
1. `close()` saves prefs (`lastPageIndex`, `nativePageIndexAtOpen`) then `PluginManager.closePluginView()`.
2. `overlay/index.js` wraps `closePluginView` once per activation and calls `handoffLastSavedPage()` first (failure is logged, close continues).
3. Kotlin `handoffLastSavedPage` reads `lastPageIndex` from the just-saved prefs JSON, finds Supernote's `CONFIG/config.data` by PDF inode, verifies inode + URI, rewrites `currentPage` (verified reread; restores original bytes on failure), then `scheduleDocumentRestart`. It skips entirely if a native-mark recovery fence/annotation recovery is pending.
4. Worker: sleep 900 ms, re-check fence, sample `com.supernote.document` PIDs (null sample => throw, no kill), `SIGKILL` each, wait for exit, sleep 450 ms, re-check fence, `startActivity(DocumentActivity, NEW_TASK|CLEAR_TASK)`.
5. On next RTL launch `decodePreferences`: saved RTL page wins iff native page == `nativePageIndexAtOpen`; else native page wins (hardware-validated in REGRESSION v0.0.9 §5 for pages differing from the anchor).
- Limitation L1: if the user pages in stock back to exactly the open-time page, the saved RTL page overrides them. Pinned by a test; fixed for Edit returns.

## Edit/Return state table (implemented in `overlay/editReturn.js`, tested in `scripts/test_edit_return.js`)
Edit = save `lastPageIndex=N` + `editReturn{filePath,editPage,totalPages,nativePageAtOpen,createdAt}`, then the ordinary Close path (no new native code).
| case | result on next RTL open |
|---|---|
| E1 stock still on edited page | open at N (spread containing N) |
| E2 user paged in stock | open at stock page |
| E3 user paged back to the RTL open-time page | stock page wins (L1 fixed) |
| E4 handoff did not happen (stock still at old page) | RTL follows what stock shows |
| E5 record older than 72 h / clock skew >5 min | ignored -> legacy rule |
| E6 page count changed (document replaced) | ignored -> legacy rule |
| E7 other path / malformed / bad version / page out of range | ignored -> legacy rule |
| E8 record consumed | next save omits it |
| Rotation between Edit and return | no effect: page is orientation-free; pair derived at render (test: pair always contains N, cover on/off, RTL/LTR) |
| Blank cover slot | no Edit button for a null slot |
| Blocked: busy / authority unresolved / v2 native-spread enabled / not ready | button disabled or header notice; nothing saved or handed off |
| Save fails | abort, plugin stays open, header notice |
Remaining ambiguity: same path replaced by a different PDF with the same page count is not detectable in JS (Kotlin verifies inode+URI only when writing the native config).

## SIGKILL / unsaved-ink safety
Code guarantees: config write is verified and rolled back on failure; kill only happens after fence checks and only with a non-null PID sample; restart is blocked if a recovery fence appears.
Code does NOT: ask the stock reader to save, wait for a save acknowledgement, check pen contact/dirty state, or verify which PDF the killed process shows. The fences guard the v2 protected-marker pipeline, not stock in-memory ink.
Project evidence: v2 docs name stock save points (`saveTrails()` in page transactions; `onDestroy` "final native save") — SIGKILL bypasses `onDestroy` (Android cannot catch it). Native Spread v0.0.92 had to flush the `.mark` right after eraser pen-up because a reread restored pre-erase contents, so stock persistence is not always immediate. Hardware regressions validate landing page after Close, not ink retention across the kill; I found no recorded test of "annotate in stock -> open RTL -> Close -> kill -> verify strokes" (keyword search of REGRESSION.md).
Unknown: U1 when stock persists strokes (pen-up vs page change vs onPause/onStop/onDestroy); U2 whether opening the plugin view pauses/saves the Document activity; U3 pen contact at kill time; U4 timing for eraser/lasso/highlight.
Consequence: Edit adds no kill site but makes the existing kill user-triggerable per page. Treat E3 as a merge/ship blocker for real documents. Mitigation options if E3 fails (need hardware evidence, not implemented): graceful finish of the Document activity before restart; require a quiet interval after the last pen-up; or a stock-save ack.
