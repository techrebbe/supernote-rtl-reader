# T-006 — Saved native ink in the RTL page display

User requested proceeding with production-display integration after T005 PASS.
This task changes only read-only display; it does not implement the separate
save-safe companion endpoint or revive the custom native-writer viewport NO-GO.
Original PDF/.mark remain authoritative and unmodified.

## Bounded first candidate

0.4.24-ink-exp1/code45, normal RTL Reader plug-in identity/signing retained.
Reuse the tested transparent PNG API and owned native cache, with independent
request cancellation/cleanup and a separate bitmap drawn after PDF background.
Ink uses exactly the background destination/clip, including spread sizing.
Never bake ink into the PDF cache, change writer coordinates or retain an image
across a fresh plug-in activation without native source/mark verification.

Initial support is deliberately only the exact T004 PDF SHA/PAGE3/index2 at
canonical1404x1872. Other pages/documents keep working as ordinary PDFs, but do
not receive speculative ink mapping. Native text highlights remain unsupported.
Matching PNG dimensions alone cannot prove arbitrary PDF CropBox/rotation or
native padding: the stock PDF origin raster is centered into a fixed canvas,
while our PDF raster has the source page's aspect ratio. This first slice uses
the existing fixture hardware evidence, not an aspect-ratio inference.

Root owns App/build wiring, native worker owns module/registry/PdfPageView, JS
worker owns pure controller/tests; geometry reviewer read-only. No agent devices.
Required before candidate use: focused controller/lifecycle/generated-wiring
tests, existing invariants/core/mutations/packaging, actual signed plug-in build,
independent exact-change review and exact artifact/hash record. Frozen-source
digest updates must identify only the intentionally changed authored sources.
