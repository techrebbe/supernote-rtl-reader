# T-008 — Restricted ordinary-PDF saved-ink geometry alpha

Status: bounded source implementation in progress for ink-exp3/code47. No T008
ink hardware reservation, installation or candidate approval is implied. The
installed code46 package still supports only T004 PAGE3. Keep its exit-quiescence
correction intact while extending the same pipeline, not a parallel controller.

## Smallest useful scope

Support one vetted, disposable ordinary portrait PDF/page with existing native
saved handwriting and a visibly letterboxed background. Initially require
unrotated, zero-origin, equal CropBox/MediaBox, finite positive integer point
dimensions, UserUnit=1, and a matching Nomad portrait annotation canvas. Bind the
profile to exact source SHA, canonical path, page index and page count; capture
the unchanged native mark sidecar separately. Use fit mode only for this slice.

For the initial candidate, saved ink is exposed only in portrait single-page fit.
Landscape, rotated/nonzero-origin or unusual boxes, cross-device annotation
canvases, native-fill trimming, text-highlight completeness and arbitrary-PDF
support remain explicitly unsupported. Their future work does not block this
bounded alpha. Never present an unsupported page as annotation-free.

## Geometry contract and source evidence

The stock portrait path in `PDFMupdf.loadPage` (native-reader decompilation,
lines 224–284) obtains effective MuPDF bounds, uniformly fits the PDF raster and
centers it inside a white native canvas; it records CTM and offsets. Reuse that
fit/centering model, not the whole method: its earlier annotation appearance
updates are outside this read-only display slice. Do not mechanically copy the
decompiled landscape branch or its variable-reassignment artifacts.

For the vetted zero-origin portrait case, record effective bounds B, native
canvas W/H, the stock 160/72 scale and RectI rounding, fitted content width/height
and integer centered offsets. The background must be a W-by-H white canvas
with the PDF rendered into that content rectangle. The full native mark PNG is
a separate immutable W-by-H layer. Draw both whole canvases through the same
view destination and clip; never stretch the ink canvas onto a bare-PDF raster,
and never crop away ink solely because it lies in a native letterbox margin.

`DocumentThumbnailsUtil.generateThumbnails` independently scales PDF x/y for
SDK `generateDocImage`; equal requested PNG dimensions therefore do not prove
co-registration. SDK `getPageSize` returns the device/rotation annotation canvas,
not PDF bounds. Internal `PDFMupdf.getPdfPageBound` is read-only but is not exposed
by the existing SDK. There is no established native background/ink render-pair
export in this repo. Do not add reader-process hooks, load stock writer objects,
or assume the document app's MuPDF JNI is available inside PluginHost.

## Vetted metadata without manual conversion

Programmatically inspect a local disposable copy of an existing ordinary PDF
with read-only PDF tools: resolve inherited MediaBox/CropBox/Rotate/UserUnit,
record effective bounds, page count and source SHA, and reject values outside
the restrictions above. Generate a small explicit native allowlist/profile from
that evidence. No user conversion, PDF rewrite, annotation transplant or native
save is required. Cross-check Android effective page dimensions and SDK native
canvas dimensions at preparation; integer Android dimensions alone are not
proof of arbitrary MuPDF bounds. Copy a matching PDF/mark pair only under the
device task's approval, leaving the original pair untouched.

## Earliest decisive gate

After focused host checks and one independent review, use the actual Nomad;
do not introduce emulator or broad architecture prerequisites. Host checks cover
the portrait letterbox calculation, malformed/unsupported geometry rejection,
profile/cache mismatch and stale-page suppression, plus existing pending SDK and
failed-drain protections. Record the exact reviewed source/build identity and
known-good rollback package before any separately authorized installation.

Root alone reserves issue23 and performs a bounded disposable trial:

1. Record device/candidate identity, source/mark hashes, page, settings and owned
   output baseline. Capture the same settled page in the normal native reader,
   including background fiducials and existing handwriting; record the native
   view configuration so screenshot-to-canvas placement is not guessed.
2. Open that exact page in the alpha's portrait fit display. Compare page-frame
   fiducials, native letterbox margins and stroke support relative to the
   background, not whole-image hashes or nominal dimensions. Predeclare a
   one-native-canvas-pixel placement tolerance after registration; record PASS,
   FAIL or UNKNOWN. Check native-margin strokes too when present.
3. Only after a recorded geometry pass, perform one normal portrait page-away/back.
   Check the neighboring unannotated page, unchanged ink placement on return,
   natural owned-cache drain and unchanged source/mark. A settled landscape
   transition must report T008 saved ink as unavailable in this first candidate;
   it must not attach the portrait witness to an unverified landscape canvas.
   Return to portrait and recheck registration. This does not authorize general
   landscape annotation support or another SDK-overlap stress loop.

Hard stop on wrong document/page/geometry, changed source or mark, crash,
disconnect, unfinished SDK output or uncertain cleanup. Do not delete pending
outputs or retry as rescue. Restore changed settings, drain by ordinary page-away
and release issue23. A geometry pass is not durable-save, native-highlight or
dirty-at-kill evidence. Pending-exit testing remains the separate reviewed
code46 gate, not an automatic addition to this trial.

## Physical-input dependencies, last

No physical input is needed if a suitable matched ordinary PDF/mark pair with
saved handwriting already exists. If none is available, finish implementation,
host checks and review first, then request native pen marks on a newly generated
disposable letterboxed fixture when the user is awake. Do not transplant T004
ink onto changed page geometry to avoid that dependency. Physical e-ink/pen
quality checks and fresh-stroke/native-save persistence checks remain separate;
screen captures alone cannot establish them.

unannotated two-page source using ReportLab, validates the PDF boxes/rotation/unit
with pypdf, then publishes by exclusive file creation. Existing PDF/directory,
leaf symlink and same-name .mark are rejected; a detected concurrent sidecar
also rejects. No atomic PDF/mark paired-publication guarantee is claimed.
Original documents are never read or altered by this builder.
