# T-014 — Bluetooth page-turner, separate from the saved-ink hardware gate

Status: bounded source design only. No production key handler, paired-device
claim, permission change or hardware action. User requested this feature; it
must not be silently omitted while a pen-dependent gate is pending.

## Integration boundary

Keep Option B and the original PDF. Capture paging keys only while the RTL view
actually owns focus. A plug-in does not own PluginHost's Activity, so do not
assume an Activity override or global root key interception is available. First
inspect the existing native PdfPageView/React Native focus path and establish
whether a view-scoped Android KeyEvent listener can receive the actual HID keys
without changing touch navigation, text-entry focus or stock-reader behavior.
Do not add another native-reader hook or restart/save route for this feature.

Use the existing logical next/previous callbacks and spread step. Keep physical
left/right keys distinct from logical Next/Previous: direction changes the former,
not the latter. Make alternate remote mappings opt-in, especially volume/media
keys, which must keep their system behavior outside the focused RTL view.
Do not infer a Bluetooth model or its key codes from an injected key test.

One accepted press yields one turn; hold/repeat does not make an unbounded queue.
Classify at DOWN and retain only that contact's ownership until UP/CANCEL or an
explicit focus-loss cancellation. If settings, page jump, Edit/Close, cleanup
failure or rendering authority prevents navigation, do not queue a later turn.
Disconnect/reconnect and missing-UP behavior need an explicit bounded policy;
avoid both permanent stuck keys and replaying a press into a new activation.

## Offline checks before device use

Test actual source routing, RTL/LTR physical direction, logical page step in
Single/Spread, bounds/no-op turns, repeats and duplicate DOWN, UP without DOWN,
unknown keys, focus loss, reconnect/new activation, and every transition/modal
fence. Verify no background/stock-reader event handler remains after unmount.
Reuse existing page-transition epoch/cleanup, rather than creating a second
navigation owner. Keep this a separately reviewed candidate from T013.

## Earliest safe hardware gate

After focused host checks, one independent integration review and verified
package/signing, request a fresh exact-package disposable-only reservation.
First use a bounded injected-key check to establish the view-scoped Android
route. Record exact keys and resulting logical pages, with ordinary reader and
modal controls unaffected. Then, separately, the user presses their paired
Bluetooth turner's two buttons once each, then holds one briefly. This physical
transport gate cannot be replaced by synthetic input; capture actual event codes
before committing device-specific mapping defaults.

PASS: exact expected turns, no duplicate/queued turn, no system-key interception
outside focused RTL, correct cleanup. FAIL/UNKNOWN: stop and preserve evidence;
no global-hook rescue loop or automatic merge.
